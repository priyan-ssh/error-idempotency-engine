01 Glossary & Core Concepts

The Idempotency Engine is structured around 11 primary domain primitives designed to collapse identical error spikes, discriminate contextual variations, relate cross-system failures, and associate verified solutions.

1. Raw Text

The original, unmodified log message, exception stack trace, or standard error string emitted by an application or service prior to any processing or cleanup.

2. Normalization / Canonicalization

The deterministic transformation process that strips or replaces volatile tokens (timestamps, UUIDs, memory addresses, IP addresses, ports, ephemeral paths) with standardized placeholders like <VAR>.

3. Shape Template

The canonical string pattern produced by normalizing raw error text. Represents the structural invariant of an error regardless of runtime dynamic data.

4. Shape Hash

A deterministic 64-bit SHA-256 hash computed directly from the canonical Shape Template. Serves as the primary unique key for fast exact-match lookup.

5. Anchor (ErrorShape)

The root entity in PostgreSQL representing a unique error shape. Holds aggregate metrics (occurrence count, first/last seen timestamps) and links to variants, embeddings, and solutions.

6. Context

Key-value runtime metadata attached to an error event, such as service name, environment, framework version, region, or stack layer.

7. Context Fingerprint

A deterministic hash computed from sorted, key-value context attributes. Differentiates identical error shapes occurring in distinct runtime environments.

8. Variant (ErrorVariant)

A specific contextual instantiation of an ErrorShape paired with a Context Fingerprint. Can optionally store its own domain-specific embedding.

9. Embedding

A dense 1536-dimensional vector generated from the normalized error text. Stored in pgvector columns indexed with HNSW for semantic approximate nearest neighbor (ANN) similarity search.

10. Solution (ErrorSolution)

Resolution guidance, patch descriptions, or automated remediation steps associated with an Anchor or Variant. Supports versioning and success metrics.

11. Linking (ErrorLink)

Graph relationships established between distinct error shapes (e.g. parent/child, causer/caused-by, duplicate) calculated via background async sweeps or explicit agent triage.

03 Step-by-Step String Transformations

Walkthrough of a raw error line transforming through each normalization stage into hashes, contexts, and vectors.

1. Raw Error Event Input

An unformatted error log arrives from a watcher or API client containing volatile timestamps, IP addresses, ports, and UUIDs:

{
  "event_id": "evt_9876543210_abc",
  "raw_text": "2026-09-26T14:32:10.123Z [ERROR] Failed to connect to DB at 192.168.1.45:5432 after 3000ms. Connection ID: 4f8b9a10-89bc-4d32-90ab-123456789abc",
  "context": {
    "service": "payment-api",
    "env": "production",
    "region": "us-east-1"
  }
}

2. Text Normalization / Canonicalization

The TextNormalizer applies deterministic regex patterns to replace volatile values with canonical <VAR> markers:

<TIMESTAMP> [ERROR] Failed to connect to DB at <IP>:<PORT> after <DURATION>ms. Connection ID: <UUID>

3. Shape Hash Generation

The canonical Shape Template is hashed using SHA-256 to produce a 64-bit deterministic shape hash key:

// C# FingerprintGenerator
string input = " [ERROR] Failed to connect to DB at : after ms. Connection ID: ";
byte[] hashBytes = SHA256.HashData(Encoding.UTF8.GetBytes(input));
string shapeHash = Convert.ToHexString(hashBytes).ToLowerInvariant();
// Output: e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855

4. Context Canonicalization & Fingerprinting

Context attributes are sorted alphabetically by key, formatted as key=value pairs delimited by |, and hashed:

Canonical String: env=production|region=us-east-1|service=payment-api
Context Fingerprint: 7d8f3a9e1b2c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e

5. Vector Embedding Generation

When an anchor or variant is newly inserted (Case B or Case C), an embedding request generates a 1536-dimensional floating-point vector:

{
  "shape_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "dimensions": 1536,
  "vector_sample": [0.01234, -0.04567, 0.08901, -0.00234, 0.05678, "... 1531 more floats"]
}

04 Ingestion Process Flow

When a batch of log samples arrives at the API (via POST /v1/ingest), the system executes a 6-layer pipeline designed to maximize throughput, eliminate redundant LLM embedding calls, and prevent Postgres transaction deadlocks.

L5->>L6: INSERT ErrorShapes / ErrorVariants + pgvector HNSW L6-->>Client: 200 OK (Ingest complete) end end

Layer 1: Idempotency Gate

Exact-Once Processing

Every write transaction inserts the payload's event_id into the ProcessedIngests table using ON CONFLICT DO NOTHING RETURNING event_id. If no row is returned, the event was already processed and execution skips immediately.

INSERT INTO ProcessedIngests (event_id, processed_at)
VALUES (@EventId, NOW())
ON CONFLICT (event_id) DO NOTHING
RETURNING event_id;

Layer 2: Deterministic Ordering

To avoid database deadlocks during multi-item batch inserts across concurrent threads, samples within a batch are sorted deterministically by context_fingerprint ASC before acquiring locks or initiating database transactions.

Layer 3: Normalization & Fingerprinting

In-memory CPU execution converts raw text to canonical shape templates, calculates the 64-bit Shape Hash, and derives the Context Fingerprint.

Layer 4: Peek DB Check

Executes a fast, non-locking SELECT query against PostgreSQL to check whether the anchor (Shape Hash) and variant (Context Fingerprint) already exist.

  • Case A (All fingerprints hit): The error shape and variant are known. Skip LLM/embedding generation completely (saving time and API cost) and proceed straight to atomic count increment.
  • Case B / Case C (New Shape or Variant): Generate the vector embedding before attempting to lock. Never call embedding APIs while holding a database lock!

Layer 5: Advisory Lock Discipline

For new shapes or variants, acquire a transaction-scoped 64-bit Postgres advisory lock using pg_try_advisory_xact_lock with hashtextextended. The lock releases automatically on COMMIT or ROLLBACK.

-- 64-bit transaction-scoped advisory lock key
SELECT pg_try_advisory_xact_lock(hashtextextended('shape:' || @ShapeHash, 0));

Layer 6: Database Persist & Vector HNSW Index

Within the short locked transaction, insert the root ErrorShape, the ErrorVariant, and store the 1536-dimensional vector into the pgvector column. PostgreSQL automatically updates the HNSW index for instant semantic retrieval.
