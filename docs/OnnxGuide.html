Execution Providers, Vector Embeddings, and Intel Core Ultra NPU Integration

1. What is ONNX & ONNX Runtime?

ONNX (Open Neural Network Exchange) is an open format built to represent machine learning models. It defines a common set of operators and an extensible file format allowing models trained in PyTorch, TensorFlow, or JAX to be exported and executed across different programming languages and hardware architectures.

ONNX Runtime (ORT) is a high-performance scoring engine developed to execute ONNX models with hardware-specific optimizations via Execution Providers (EPs). Instead of rewriting model code for every chip, ONNX Runtime delegates subgraphs to underlying hardware accelerators (Intel NPU, Intel Arc GPU, CUDA, or CPU).

2. How Vector Embeddings Work in the Engine

The Idempotency Engine generates 384-dimensional vector embeddings for error signatures using the all-MiniLM-L6-v2 transformer model. These vectors are indexed into PostgreSQL via pgvector for semantic similarity search (HNSW index with cosine distance).

Embedding Generation Pipeline
1
Input Normalization: Raw error messages are stripped of non-deterministic artifacts (IP addresses, UUIDs, memory addresses, timestamps).
2
Tokenization: Text is tokenized into wordpiece tokens capped at 128 sequence length.
3
Tensor Construction: Creates three dense tensors of shape [1, 128]: input_ids, attention_mask, and token_type_ids.
4
Hardware Inference: InferenceSession.Run() executes the transformer layers across the selected hardware execution provider.
5
L2 Normalization: Mean pooling produces a 384-float vector which is L2-normalized to unit sphere length for accurate cosine similarity calculation.

4. Intel Core Ultra NPU Deep Dive

Intel Core Ultra (Series 1 & 2 / Meteor Lake, Arrow Lake, Lunar Lake) processors integrate a dedicated Neural Processing Unit (NPU). Unlike CPUs that execute instructions imperatively, the NPU requires a graph compiler to translate the ONNX computation graph into an NPU instruction stream.

Linux NPU Software Stack
  • Hardware Silicon: Intel Core Ultra Processor (PCI ID 00:0b.0)
  • Kernel Module: intel_vpu driver exposing character device /dev/accel/accel0
  • User-space Driver: Intel Level Zero driver (libze_intel_npu.so & libze_loader.so)
  • Graph Compiler: libopenvino_intel_npu_compiler.so via libnpu_driver_compiler.so
  • Execution Provider: libonnxruntime_providers_openvino.so
Zero CPU Fallback: When the Level Zero driver loads libnpu_driver_compiler.so, the ONNX model is compiled directly into an NPU blob without emitting runtime CPU fallback warnings.

5. Setup & Reproduction Guide

Step 1: Install Linux NPU User-space Drivers (One-time host setup)

Install the official Fedora/RHEL or Ubuntu packages:

# Fedora 40 / 41 / 44
sudo dnf install --setopt=install_weak_deps=False intel-npu-driver oneapi-level-zero

# Ubuntu 24.04+ / Debian
sudo apt install intel-level-zero-npu libze-loader1

Step 2: Run the Automated Native Runtimes Setup Script

Because precompiled native Linux OpenVINO C++ binaries, compilers, and the ONNX model are ~420 MB total, they are excluded from Git to prevent repository bloat. Run the bundled setup script to install them directly into src/IdempotencyEngine.Data/Runtimes/ and src/IdempotencyEngine.Data/Models/: 

./scripts/setup-onnx-runtimes.sh

Step 3: Export LD_LIBRARY_PATH for NPU Compiler Discovery

The Linux Level Zero driver requires the NPU graph compiler to translate ONNX models into hardware execution streams. Export the runtime directory in your shell: 

export LD_LIBRARY_PATH="$PWD/src/IdempotencyEngine.Data/Runtimes/linux-x64/native:$LD_LIBRARY_PATH"

Step 4: Configure Target Hardware in appsettings.json

{
  "OnnxHardwareOptions": {
    "ExecutionProvider": "OpenVINO",
    "DeviceType": "NPU",
    "DeviceId": 0
  }
}

Step 5: Build & Verify Tests

Run the solution test suite to verify that NPU inference executes cleanly:

dotnet build
dotnet test
